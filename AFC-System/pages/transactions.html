    Filter behaviour

    The search box, date picker, operator dropdown and status filter are interface placeholders. Filtering requires JavaScript or server-side querying, which is scheduled for the next development phase.

    Transaction lifecycle

    A transaction is created when a passenger exits a gate, priced by the fare module, then batched per operator at the 23:59 cut-off and compared against the operator settlement the next working day.

    Failed transactions

    Failures fall into three groups: insufficient wallet balance, expired or suspended tickets, and declined reversals. Failed transactions carry a zero fare value and are excluded from settlement totals.
